Check the shot list before the crew leaves.

SceneGap Edge helps a crew review the shot list against the footage on their own computer. It finds candidate clips with their original timecodes, checks each rule (length, takes, same frame) and shows pass, fail or can't tell with the clip to play. A person decides every shot; shots without a usable clip go on a reshoot list. Nothing is uploaded. Automatic missing-shot detection is the next step, not a claim.

The problem

Missing shots are found in the edit, after the location is gone.

Small crews shoot from a list of must-have shots. Nobody has time to scrub every card before packing up, so gaps show up at the editing desk, when a reshoot is expensive or impossible.

How it works

Requirement, evidence, decision.

Every answer keeps its evidence: which file, which frames, which timecode, which rule passed or could not be decided. The model ranks; a person decides.

  1. Write the shot list

    Chinese wording from the script, plus an English query a person confirms for the model. Rules: minimum continuous length, number of takes, what must appear together. Every edit is a new revision.

  2. Index the footage

    Read-only. Probe, SHA-256 (a copy is not a second take), cut shots, sample about 1 frame per second on the original timecode, embed each frame with CLIP ViT-B/32.

  3. Check the rules

    A frame passes when its similarity reaches τ, a threshold calibrated on dev footage and frozen. Length uses conservative bounds; undecided windows are re-sampled every 250 ms. Each check is pass, fail or unknown, and unknown never counts as pass.

  4. A person decides

    Accept, reject with a reason, adjust the range, or send the shot to the reshoot list. The AI answer and the human answer are stored and shown separately.

What the AI can say about a shot

candidate partial not found unverifiable not analysed

Never "done". "Not found" means nothing reached τ in the analysed footage, not proof of absence.

What only a person can say

accepted rejected, with reason accepted as exception

Actions, readable brand text and composition are manual in this version: the system ranks where to look. Coverage counts human-confirmed and AI-candidate shots separately.

Why missing-shot detection fails (dev only, after the test)

τ = 0.225 was chosen for frame-level F1, so almost every shot finds some candidate and none is reported missing. Raising τ trades gaps found against reshoots asked for wrongly:

Why this split

Only the image tower goes to the NPU, so quantization error sits on one side and G1 can measure it directly. Text queries are few per project, so the host handles them.

At 1 frame per second most of the time is decoding on the host. The NPU's job is to keep the editing machine's CPU and GPU free, not to make the total much shorter.

The G1 script is ready and was checked CPU against GPU (cosine 1.0, ρ 0.99999); that proves the script, not the device. If G1 fails, the plan in order: recompile with dev frames for calibration, keep the last layers at 16-bit if the compiler allows, switch to TinyCLIP with a new reference, or stay on the CPU/GPU reference.

First the device and missing-shot detection; then the checks that are manual today.

  6. S2-4Composition from detector boxesPrecision ≥ 0.90 on dev composition labels
  7. S2-5OCR for Traditional Chinese brand textExact match ≥ 0.90, false-readable ≤ 0.02
  8. S2-6Action aid, optional VLM verifierThe verifier stays manual unless precision ≥ 0.95 at recall ≥ 0.5
